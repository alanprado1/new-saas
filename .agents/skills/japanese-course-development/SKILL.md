# Japanese Course Development

Build lessons as content/configuration for the existing shared course engine. Read `apps/web/content/busuu/README.md` for current implementation status, then the assigned packs and relevant modules. Read [the project map](references/project-map.md) only for file routing or check selection. Earlier README sections and handoffs are historical; the latest owner instructions take precedence.

## Reuse and author

- The owner authorizes exact retained wording, documented paraphrases, and newly authored Japanese content based on documented learning targets. Ordinary missing literal wording should be resolved with reviewed production content, rather than leaving otherwise implementable lessons as previews.
- Preserve recorded sequence, canonical IDs, known response counts, register, support timing and contextual dependencies. Review Japanese, readings, translations, answer mappings, distractor ambiguity and dialogue reuse. Record authored/adapted origin internally without calling it an observed source quotation.
- Use current app TTS and replaceable visual slots. Original images/video are deferred. Exclude speaking and pronunciation exercises: no speaking choices, microphone/recording controls or speech assessment in course UI. Remove existing course speaking actions when encountered. Free writing remains optional and production never blocks chapter completion; all teaching and non-speaking practice embedded in fluency lessons remain required. Historical source speaking surfaces remain evidence, not enabled app actions.
- Select existing renderers and configured variants. Change shared components/styles for improvements meant to apply across lessons. Add a renderer capability only for a genuinely new interaction; avoid copied lesson components or conditions keyed to a particular lesson ID.
- Transcript-free listening must keep Japanese script, translations and answers out of pre-answer DOM, accessibility text and tooltips. Audio may contain the hidden source; visible support uses occurrence-specific configuration.
- Register reviewed packs through the central registry. Preserve released content versions and fingerprints used by saved attempts; create a new version when content changes. For learner-text sweeps across many packs, reuse the baseline/transform/invariance workflow in the project map ("Text-only content versions"); learner-facing English is Australian, readings are run together without word spaces, and learner text never mentions the app, engine, source material or animation replacement. Presentation-only changes should remain shared. Changes to grading/events require an explicit old-attempt compatibility decision.
- Use shared `ordering` / `ordered_tokens` for sentence chunks and `gaps` / `ordered_slots` for characters or stems. Give every physical token a unique ID; equivalent repeated text may be accepted in multiple slots/orders without allowing an ID to be reused. Removal/reinsertion uses existing token events; final placement alone opens graded feedback. Keep supplied stem endings outside the inserted answer.
- A schema 1.1 pack can declare its required core and separate optional writing surfaces. Keep retained structural evidence/counts intact; validate the complete canonical partition and source identities. Runner progress/results count required screens only; optional writing emits no attempt events. Existing schema 1.0 packs/results retain their event and result shapes. Checkpoint pass reporting is an explicit configurable app policy, separate from core completion and raw accuracy; do not infer threshold boundaries or unlock enforcement from source-account results.

## Choose checks by the change

| Shared rendering, support or audio behavior | Focused component/engine tests and affected existing variants; briefly inspect genuinely changed UI. |
| Grading/events, ownership or persistence | Relevant evaluator/client/API and isolated database regressions, including old content versions and account isolation. |

Complete required checks once after the increment. Expand checks for a failure or concrete changed dependency. Screenshots are optional evidence for changed visual behavior, not a per-screen deliverable. Do not repeat whole-course research, full database harnesses for content-only edits, or unchanged browser walkthroughs. This guidance does not waive checks required by repository instructions or the current task.

Read only the assigned record subset from existing local references. Consult deeper evidence for unresolved teaching structure or a new interaction. New live Busuu capture, hosted deployment and unrelated data operations require their own task authorization; this skill grants none.

## Keep reusable knowledge current

When implementation demonstrates a reusable capability or recurring trap, update the relevant shared code and make a short correction to this skill/project map. Prefer the existing skill; introduce another only for a distinct recurring workflow. Create a helper script when it replaces repeated deterministic work and test it against real inputs. Keep current lesson status in the implementation README, not this skill; keep raw evidence in its original files. Do not turn one lesson's parameters into universal rules.

Finish with playable lessons, shared changes, focused validation and material remaining gaps. Preserve app data, source evidence and existing features within the assigned scope.

## Shared checked input, kanji and listening variants

- Use `typed` / `AnswerSpec.typed` with explicit reviewed `acceptedForms` and `normalization: nfkc_trim`. Normalization is NFKC plus outer trim only: no universal kana folding, romaji conversion, suffix removal or internal-space deletion. Put supplied suffixes/okurigana in `typed.before/after`. Drafts use bounded `typed_draft` events; only `typed_check` grades. Drafts persist through the existing account-owned replay/outbox and may save before audio finishes; Check does not require playback. Preserve IME candidate-confirmation Enter (composition, isComposing and keyCode 229); test component handlers, not only a helper. Old states gain no typed field until a typed screen; old events/results and exact fingerprints stay unchanged.
- Configure transcript-free truth with `truthMode: audio_only`, hidden source contract, required audio and feedback-only Japanese/English. Supported truth remains strict about visible Japanese. Check pre-answer DOM/accessibility/tooltips as well as visible support; do not relax all truth readiness.
- Use the shared `kanji` teaching model for a complete static glyph/shape note, readings, meaning and contextual examples. Identify it as an animation replacement; do not invent observed stroke order or treat visual mnemonics as etymology. Shape notes and word-specific readings belong in packs.
- Ordering may have `fixedPrefix` outside selectable chunks and response counts. Document authored supplied text when retained evidence gives only an anchor constraint. Keep removal/reinsertion within movable slots, and explicitly accept reviewed equivalent discourse orders rather than grading a grammatical alternative wrong.
- Legacy raw records may omit optional-production metadata. `getRuntimeCompletionMetadata` projects only a retained tail `community_production` endpoint; alignment still verifies the complete canonical core/optional partition and source identities. Keep raw records unchanged. Core source exercise numbers can be retained in `sourceContract.sourceExerciseNumber` and are alignment-checked when present.
- Checked-input/event changes warrant evaluator, component, API/client and isolated database checks: empty/wrong/right checks, Unicode, malformed fields, clearing/partial drafts, offline retry/reload, feedback lock, multi-activity resume, old versions and account isolation. Content-only increments reuse those verified mechanics.

## Dialogue, scene context and configured listening retry

- Dialogue speaker IDs remain `guest`/`staff` for audio compatibility. Configure `context`, `speakerLabels` and `translationVisible` per occurrence; omitted translation visibility preserves released English support. Japanese-only dialogue uses explicit null English turns, complete Japanese/readings and ordered all-turn TTS. Do not expose hidden translations through support blocks or accessibility text.
- Cross-lesson `sceneContext` binds an exact registered `recordId`/`contentVersion`/`screenId` and a named dialogue fact (a verified turn excerpt) to the accepted choice ID/text. Readiness resolves the exact registry in both server and fresh browser sessions. Keep delayed questions free of source support, hints, player and replay, including feedback replay; provide accessible separate scene review before launch for standalone access, without adding counted tasks or source unlock requirements. Same-lesson `sceneReuse` remains available for supported integrated comprehension.
- `retryPolicy: { kind: 'end_once', screenIds }` opts in unique transcript-free audio truth/choice occurrences only. Wrong first outcomes queue once after all base screens, with a reset `audioReady` and separate retry outcomes; first-attempt accuracy stays immutable. Finishing the retry pass, even wrong, permits core completion. Retry fields are conditional on opted-in packs/actual retry traversal; old state/result/event shapes and fingerprints remain unchanged. Existing validated response events save retries through server replay and account-owned outboxes. Activity-boundary or token-task remediation needs an explicit extension rather than silently changing this contract.

## Multiple selection and activity-boundary review

- `multi_choice` uses `requiredCount`, `grading: exact_set` and unique `acceptedOptionIds`. Count physical selections in the source contract, but grade one base screen only on `selection_check`; `toggle_option` saves editable selected/deselected IDs without grading. Exactly the configured count enables Check. No partial credit or selection-order dependence. The optional `selectedOptionIds` state exists only on these screens; old events/state/results retain their shapes.
- `retryPolicy: { kind: 'after_activity_once', screenIds }` explicitly extends remediation to transcript-free audio truth/choice and validated `gaps`/`ordered_slots` or `ordering`/`ordered_tokens`. Missed configured occurrences return once at the end of their canonical internal activity, then resume its next base screen; final-activity retries may lead to results. Reset tokens/selections and `audioReady`. Active retry has `returnIndex`, completed boundary outcomes live in conditional `retryOutcomes`; immutable base outcomes/accuracy and unique visited counts stay separate. A wrong retry still permits completion. Keep legacy `end_once` restrictions and exact state/result shape unchanged. Feedback must use `getCurrentOutcome`, including ordering colors.
- `sceneReuse` drives the full bound dialogue's ordered TTS via **Replay scene**, not just a caption or the current answer sentence. Corrected-sentence feedback audio remains separate. No scene link means no inherited replay. Validate the actual component playback handler and scene identity, including the final unsupported listening occurrence. English-hidden dialogue retains null English turns; readings serve TTS without introducing a hidden English layer.
- Tables ending in a reading column need explicit English support; do not derive a translation from kana cells. Reviewed grammatical chunk orders may move time/means/object phrases; configure accepted equivalence in the pack rather than globally accepting arbitrary permutations.

## Summary-only app structure and limited scene glosses

- A reviewed `structuralContract` (`summary_authored`, version 1.0) supplies an explicitly app-owned canonical activity/task partition when retained evidence is `summary_only` with no individual source rows. Empty retained activity records are supported only when their task arrays remain empty and every known activity ID, ordinal, source-ID list and count matches the authored partition; unknown counts may remain null. Keep raw `LessonSpec` screens/activities unchanged. Registry alignment requires the retained total, app provenance/review, exact canonical partition and independently checked app physical response counts. Unknown task source screen/activity/exercise/renderer identities and response counts stay null. Readiness reports observed `knownScreenRows` separately from `authoredScreenRows`; no generic alignment bypass or state/event change is needed.
- Japanese-supported dialogue can explicitly configure `dialogue.glosses` with a bound Japanese term, reading and English lexical gloss. This is separate from `translationVisible`; null English turns and hidden English transcript remain intact. Readiness binds each term to a visible Japanese turn and rejects hidden/unbound/duplicate glosses. A limited gloss does not authorize full translations.
- Transcript-free ordering keeps its selectable response bank visible while withholding the full source, translation and answer order from pre-answer DOM/accessibility. Test the bank as well as hidden support. Accepted legitimate word readings and discourse orders belong in per-occurrence answer sets, including any equally valid bank distractor.
- An explicitly documented no-source-replay task sets `audio.beforeAnswer: false` and `required: false`; its answer script may remain for corrected feedback. The shared control and playback handler both enforce this, including stale handlers. Do not treat a false transcript flag alone as evidence of required listening. Omitted flags preserve released behavior.
- `sourceContract.feedbackTranscript: 'omitted'` permits documented cue-only audio truth feedback only with retained `transcript_in_feedback: false`; omit the complete source and corrected-sentence replay. Keep supported source and response-option readings separate from feedback. `transcriptAccess: 'scene_recap'` configures an optional closed full-scene recap, bound to the exact earlier complete visible dialogue, rather than inline Japanese support.
- English-only cultural table teaching can retain visible English when Japanese support is explicitly false and English explicitly true; graded transcript-free tasks remain strict. Retained tail `production_choice` and the explicitly evidenced `production_choice_v1` alias use the same optional private-writing projection as `community_production`; none changes required task counts or emits course events. Keep this an exact shared alias allowlist: do not strip arbitrary renderer suffixes or add lesson-ID exceptions.

## Parallel source readings and content-only saved paths

- `parallel_kana_available: false` requires stripping `secondary` from pre-answer Japanese source support blocks in the occurrence assembler. `sourceContract.parallelReadingBeforeAnswer` records the permission but the shared `Support` component does not mask an already supplied reading. Keep documented lexical table cells, static kanji readings/examples and legitimate response-option readings; these are separate teaching/response layers. Omitted flags preserve released behavior.
- For a content-only chapter with unchanged events/persistence contracts, verify its actual registered API/client/evaluator completion and reload paths with the disposable storage adapter, including unique map accounting and documented retry outcomes. Reuse established isolated PostgreSQL/ownership/transport baselines. A memory adapter is not fresh RLS/database evidence.

## Structured media and evidence-bound scene support

- Retained media may be objects with `kind`, controls and nullable quality rather than strings. Inspect kinds deliberately. Empty media arrays do not erase explicit scene-video/control prose; preserve that evidence and document the narrow occurrence assembler decision. A generic rendered player does not establish video or acoustic quality.
- `feedbackTranscriptResolution` (`retained_prose`, version 1.0, field `rawFeedbackParaphrase`) can resolve a null feedback flag only for required transcript-free audio truth/choice. Require explicit no/without full transcript prose and its exact observed occurrence reference/hash; alignment binds the unmodified retained quote and flags. It cannot override true flags. Omission excludes complete scripts/readings even with added whitespace, decoration or explanation/secondary placement. Released false-flag omission behavior remains valid; audio-only readiness remains strict.
- A dialogue with `kind: single_speaker` requires exactly one configured guest/staff role and `sourceContract.recordedSpeakerCount: 1`, aligned to retained `media_structure.speaker_count: 1`. Keep every ordered Japanese turn/reading and configured visible layer. Both the player caption and accessible scene label name the configured speaker. Omitted kind retains the existing two-role conversation contract; never invent another speaker to pass readiness.

## Lesson audio prefetch and persistent clip cache

- `lib/busuu/audio-plan.ts` `getScreenPlayback` is the single definition of what a screen plays (source/dialogue turns/feedback); the Replay handler and `planLessonPrefetch` both use it, so new audio variants (e.g. a new `audio` flag) must be expressed there, not in `LessonRunner`. The runner prefetches the whole lesson once the account is known, current screen first, via `CourseAudioAdapter.prefetch` (2 concurrent, silent, no UI state, never counts as playback).
- `lib/busuu/audio-cache.ts` persists clips in the Cache API (`course-tts-v1`), keyed by SHA-256 of account+provider+voice+reading+text (speed is client `playbackRate`, not part of the key); bounds: 1000 entries / 100 MB / 30 days, oldest first. Without Cache API/crypto (insecure origin) prefetch is a no-op. Playback order: memory, joined in-flight prefetch, persistent cache, network. Tests: `lib/busuu-audio-prefetch.test.mjs`.

## Lesson runner shell (Busuu layout and behaviour)

- Playback is optional everywhere: `transitionLesson`/`canContinue` no longer read `audioReady`. The field, the `audio_ready` event and its `enter()` reset stay, so saved streams replay to identical states (fixture test `lib/busuu-lesson-runner-ui.test.mjs`, player in `lib/busuu-playback-compat-player.mjs`). The runner still dispatches `audio_ready` after a completed play; it never gates and scene-reuse questions play only on demand (Replay scene).
- Grading is by tap: choice/truth grade in one event; `multi_choice` dispatches `toggle_option` then `selection_check` on the last required pick (no Check). Only typed keeps Check (docked inside `TypedAnswer`). Enter = the visible `[data-primary-action]`, 1-9 = `[data-shortcut]` (`handleLessonKey`, with IME guards).
- The runner is a fixed full-viewport shell (`runner.module.css`, palette in the `.shell` custom properties; `--c-primary` follows `--course-accent`). Feedback is a bottom sheet re-hosting only `getFeedbackSupport` (after blocks minus anything visible before answering); keep its buttons' text as plain strings ('Replay audio', 'Replay scene', 'Replay corrected sentence'): component handler tests find them by text, and `LessonRunner` hook order (useState 1 state, 2 save, 3 audio, 4 preferences, 5 speed, 6 accountReady) is relied on by those tests, so append new hooks at the end.
- Progress is per canonical activity incl. boundary retries (`getActivityProgress`, presentation only). Retried screens have no banner. Leaving mid-lesson asks inside the runner before disposing the session.
- Audio player is one pill (play/pause toggle, indeterminate progress sweep, speed select); the voice picker is a popover from the top-bar icon button. The toggle's accessible name ('Replay audio' / 'Replay scene' / 'Pause audio' / 'Retry audio') is its `aria-label`, so component handler tests find it via `props['aria-label']`; its `onClick` still returns the play promise. Status text is a visually hidden live region; only errors are visible. The popover state is the last `useState` (12th) in `LessonRunner`.
